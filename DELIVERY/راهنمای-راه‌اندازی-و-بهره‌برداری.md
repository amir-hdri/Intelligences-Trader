# راهنمای راه‌اندازی، پیکربندی، پشتیبان‌گیری و تحویل

پروژه: **Intelligences-Trader** — پلتفرم معاملات الگوریتمی بورس کالای ایران
نسخه: 2.5.0+ (کامل‌شده فول‌استک)

---

## ۱. پیش‌نیازها

- **Node.js 22.13+** (یا 26) — پایگاه‌داده از ماژول داخلی `node:sqlite` استفاده می‌کند؛ نیاز به سرویس DB خارجی ندارد.
- Python 3.12 (فقط برای `ml_service`؛ اختیاری در مسیر اجرای روزانه).
- Docker + Docker Compose (برای استقرار کانتینری).
- مرورگر با پشتیبانی `SharedArrayBuffer` (برای workerهای تحلیل).

## ۲. نصب و اجرای محلی (بدون Docker)

```bash
# 1) ساخت فایل‌های محیطی (اجباری — بک‌اند بدون JWT_SECRET بالا نمی‌آید)
cp "robot trader/server/.env.example" "robot trader/server/.env"
cp server/.env.example server/.env
# سپس در هر .env مقدار JWT_SECRET / REFRESH_SECRET را به رشته‌ای تصادفی قوی تغییر دهید.

# 2) پراکسی داده (پورت 3001)
cd server && npm install && npm start

# 3) بک‌اند تحلیل + پایگاه‌داده (پورت 3000)
cd "../robot trader/server" && npm install && npm start
# در اولین اجرا، پایگاه‌داده data/trader.db ساخته، migrationها اجرا و admin اولیه seed می‌شود.

# 4) فرانت‌اند (پورت 5173)
cd "../robot trader" && npm install && npm run dev
```

## ۳. متغیرهای محیطی

| متغیر | سرویس | الزامی | توضیح |
|---|---|---|---|
| `PORT` | هر سه | خیر | پورت (پیش‌فرض: 3000 بک‌اند، 3001 پراکسی) |
| `JWT_SECRET` | بک‌اند، پراکسی | **بله** | امضای access token؛ در نبودش `process.exit(1)` |
| `REFRESH_SECRET` | بک‌اند | **بله** | امضای refresh token |
| `DB_PATH` | بک‌اند | خیر | مسیر SQLite (پیش‌فرض `./data/trader.db`؛ در داکر `/app/data/trader.db`) |
| `ADMIN_USERNAME` | بک‌اند | خیر | نام کاربری admin در seed اولیه (پیش‌فرض `admin`) |
| `ADMIN_PASSWORD` | بک‌اند | توصیه | رمز admin در seed؛ اگر نباشد، رمز تصادفی تولید و یک‌بار در لاگ چاپ می‌شود |
| `CORS_ORIGIN` | بک‌اند، پراکسی | خیر | origin مجاز CORS (پیش‌فرض `http://localhost:5173`) |
| `NODE_ENV` | هر سه | خیر | `production` سطح لاگ info و غیرفعال‌سازی pino-pretty |
| `VITE_BACKEND_URL` | فرانت (بیلد) | خیر | آدرس بک‌اند تحلیل (پیش‌فرض `http://localhost:3000`) |
| `VITE_PROXY_URL` | فرانت (بیلد) | خیر | آدرس پراکسی داده (پیش‌فرض `http://localhost:3001`) |
| `VITE_WS_URL` | فرانت (بیلد) | خیر | آدرس وب‌سوکت (پیش‌فرض `ws://localhost:3001`) |

تولید secretهای تصادفی قوی (برای `secrets/` مورد ارجاع docker-compose قدیمی):

```bash
bash scripts/generate-secrets.sh
```

## ۴. پایگاه‌داده و migration

- اسکیما در `robot trader/server/db/migrations/001_init.sql` (idempotent).
- جدول‌ها: `users`, `predictions`, `trades`, `audit_events`, `settings`, `market_snapshots`.
- migrationها به‌صورت خودکار در بوت اجرا می‌شوند (فایل‌های `*.sql` به ترتیب الفبایی).
- seed اولیه: ساخت admin + یک رکورد audit + تنظیمات ریسک پیش‌فرض (فقط وقتی جدول `users` خالی است).

**پشتیبان‌گیری:**

```bash
# الف) با توقف سرویس — ساده‌ترین راه: کپی فایل
cp "robot trader/server/data/trader.db" backup-$(date +%F).db

# ب) بدون توقف (WAL checkpoint اول)
sqlite3 "robot trader/server/data/trader.db" "PRAGMA wal_checkpoint(TRUNCATE);"
cp "robot trader/server/data/trader.db" backup-$(date +%F).db
```

**بازیابی:** سرویس را متوقف کنید، فایل پشتیبان را در `robot trader/server/data/trader.db` بگذارید و سرویس را بالا بیاورید.

## ۵. استقرار با Docker Compose

```bash
# از ریشه پروژه
cp "robot trader/server/.env.example" "robot trader/server/.env"
cp server/.env.example server/.env
# مقداردهی secretها در .env
docker compose up --build
```

- فرانت روی `:5173`، بک‌اند روی `:3000`، پراکسی روی `:3001`.
- پایگاه‌داده در volume `./robot trader/server/data` ماندگار می‌شود.

## ۶. استقرار Kubernetes (مرجع)

- `k8s/secret.yaml` یک **قالب** است با مقادیر placeholder — هرگز secret واقعی commit نکنید؛ قبل از `kubectl apply` مقادیر را با ابزار مدیریت secret (SealedSecrets / External Secrets) جایگزین کنید.
- تصاویر ساخته‌شده توسط CI/CD (`ghcr.io/<repo>/<service>:<sha>`) باید با `image` در `k8s/deployment.yaml` هم‌راستا شوند (استپ deploy در CI/CD هنوز وصل نیست — مورد باز).

## ۷. احراز هویت

- ورود در UI از تب **Settings → Account Authentication**.
- پیش‌فرض: کاربر admin که در بوت seed شده (رمز از `ADMIN_PASSWORD` یا رمز تصادفی لاگ‌شده).
- endpointهای `predictions` / `trades` / `audit` به توکن `Authorization: Bearer <token>` نیاز دارند.
